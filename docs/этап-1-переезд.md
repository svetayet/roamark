# Этап 1: переезд на локальное хранилище

Что изменилось: приложение больше не просит email и не ходит в Supabase.
Все треки и районы теперь хранятся в самом браузере (это называется IndexedDB) —
открывается мгновенно и работает без интернета. Синхронизация между
устройствами (Яндекс.Диск проверен и не подошёл, проверяем GitHub) —
следующий этап.

## Что сделать тебе (один раз, ~5 минут)

1. **Открой сайт** на компьютере и на телефоне — сразу попадаешь в библиотеку,
   никаких экранов входа. При первом открытии появится район «Рядом».
2. **Перенеси районы руками**: в старом приложении у тебя было несколько
   районов (треков в них — ноль). Создай те же районы в «настройках»
   нового приложения и назначи основной, как было.
3. **Проверь**: добавь один трек, открой его, нажми «скачать GPX» —
   файл должен скачаться и открыться в навигаторе как раньше.
4. **Удали проект Supabase**: supabase.com → твой проект → Settings →
   General → Delete project. Делай это только после шагов 2–3 — когда
   убедилась, что новое приложение работает.
5. **Убери секреты из GitHub**: репозиторий → Settings → Secrets and
   variables → Actions → удали `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
   Деплой их больше не читает, но хранить лишнее незачем.

## Важно знать

- Данные живут **в браузере устройства**: если почистить «данные сайта»
  в браузере — треки уйдут. Пока синхронизации нет, не чисти данные
  браузера и не удаляй приложение на телефоне, где лежат треки.
- Режим инкогнито забывает всё при закрытии окна.
- «Установить на главный экран» (PWA) работает как раньше.

## Проверка Яндекса для синхронизации: проверили — не подошёл

Яндекс.Диск прогнали через страницу `#/spike` по всей цепочке: папка
создаётся, файл заливается — а вот **скачать свой же файл браузеру Яндекс
не даёт**: сервер отвечает 403 без CORS-заголовка. Причём тому же файлу
с той же машины, но не из браузера, Яндекс отвечает «пожалуйста» —
то есть он различает, кто спрашивает, и браузеры на чужом сайте не
пускает. Права у токена были полные, дело не в них и не в нас.

Приложение `roaMark` на [oauth.yandex.ru](https://oauth.yandex.ru)
больше не нужно — можешь удалить его там (или просто отозвать доступ).

## Проверка GitHub для синхронизации (spike)

Второй кандидат — GitHub: синхронизация будет хранить треки в папке
твоего же репозитория. Страница `#/spike` прогоняет всю цепочку
(токен → репозиторий → залить файл → прочитать → скачать байты → убрать
за собой) и говорит прямо, подходит GitHub или нет.

Как получить токен для проверки — см. раздел «Токен GitHub» внизу
этого файла.

## Токен GitHub (для страницы #/spike)

1. Зайди на [github.com](https://github.com) под своим аккаунтом →
   Settings → Developer settings (внизу слева) → Personal access
   tokens → **Fine-grained tokens** → Generate new token.
2. Token name: `roaMark spike`. Expiration: **7 дней** — для проверки
   хватит с запасом.
3. Repository access: **Only select repositories** → `svetayet/roamark`.
4. Permissions → Repository permissions → **Contents** →
   **Read and write**. Больше ничего не отмечай — токен сможет только
   читать и писать файлы в этом одном репозитории.
5. Generate token → скопируй `github_pat_…` (его показывают один
   единственный раз).
6. Открой на сайте `#/spike`, вставь токен в поле → «проверить».
   Токен остаётся только на этой странице и никуда не сохраняется.

Если проверка завалит какой-то шаг — напиши мне, какой именно.
