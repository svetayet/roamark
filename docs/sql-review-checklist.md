# Чеклист ревью SQL-миграции (supabase/migrations/0001_init.sql)

Пройдись по пунктам перед первой настройкой и после неё.
Ставь галочки, когда пункт проверен на живом проекте.

## Безопасность

- [ ] `alter table ... enable row level security` есть у **обоих** таблиц (`districts`, `tracks`).
- [ ] Все политики данных — только через `auth.uid() = user_id` (`owner_all_districts`, `owner_all_tracks`), без политик для `anon`/`public`.
- [ ] Бакет `gpx` создан приватным (`public = false`).
- [ ] Политика `owner_gpx_objects` ограничена `bucket_id = 'gpx' and owner = auth.uid()` — не распространяется на другие бакеты.
- [ ] Анонимный доступ отсутствует: до входа REST-запросы к таблицам и файлам возвращают пусто/ошибку.

## Целостность

- [ ] `tracks.district_id ... on delete restrict` — удалить район с треками нельзя ни из приложения, ни напрямую из БД (ошибка 23503, приложение показывает «сначала перенесите их в другой район»).
- [ ] Триггер `trg_single_primary` держит **ровно один** основной район: после `update districts set is_primary = true where id = <новый>` у старого флаг снят.
- [ ] Ограничения длины: название района 1–100, трека 1–200, описание ≤1000.
- [ ] `category` — enum из четырёх значений (`hike`,`bike`,`run`,`ski`).

## Закрытая регистрация

- [ ] Триггер `trg_one_owner` **не мешает первому** входу: свежий проект, первая magic-link почта входит свободно.
- [ ] Вторая почта отклоняется ошибкой «Регистрация закрыта».
- [ ] Понятно, что «свой Supabase у каждого» снимает вопрос: у другого человека — свой проект и своя миграция.

## Совместимость с приложением (Task 9)

- [ ] Колонки snake_case совпадают с маппингом репозитория: `distance_km`, `original_filename`, `storage_path`, `min_lat`…`max_lon`, `preview`, `created_at`.
- [ ] Клиент задаёт `id` и `created_at` явно — дефолты колонок их не перекрывают.
- [ ] `preview` — строка формата `«lat,lon;lat,lon|lat,lon…»` (`encodePreview`/`decodePreview`).
- [ ] Файлы складываются как `{uuid}.gpx`, скачивание — `createSignedUrl(path, 3600)`.
