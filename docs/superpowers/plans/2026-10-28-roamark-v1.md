# roaMark v1 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Личная библиотека GPX-треков: мобильный SPA на GitHub Pages + Supabase free, с добавлением треков по одному, районами, страницей трека с картой и скачиванием оригинала.

**Architecture:** Статический SPA (Vite+React+TS), весь доступ к данным через один интерфейс `TrackRepository` с двумя реализациями — InMemory (демо/тесты) и Supabase (прод). Растровые карты Leaflet (CyclOSM / CARTO dark по теме). Тема — CSS-переменные + `[data-theme]`.

**Tech Stack:** Vite, React 18, TypeScript strict, Vitest + Testing Library (jsdom), Leaflet, react-router-dom (HashRouter), @supabase/supabase-js, vite-plugin-pwa, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-28-roamark-design.md` — план исходит из спеки; исполнители читают обе.

## Global Constraints

- Node 20+, npm. TypeScript `strict: true`. В конце каждой задачи `npm run build` и `npx vitest run` обязаны быть зелёными.
- UI полностью на русском; числа через `ru-RU` (запятая в дробях).
- Палитра «ель» — точные токены из спеки, в `src/styles/tokens.css`, темы переключаются атрибутом `[data-theme='light'|'dark']` на `<html>`; по умолчанию «как в системе».
- Mobile-first: работает от 360 px, без горизонтального скролла.
- Supabase упоминается только в `src/data/supabase/*`; остальной код — через `TrackRepository`. Секреты фронтенда: только `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`; `service_role` запрещён.
- Исходный `.gpx` не мутируется; путь в Storage `{uuid}.gpx`; скачивание под именем `originalFilename`.
- Атрибуция карты не отключается.
- Роутинг: HashRouter (страницы GitHub без rewrite).
- Коммит в конце каждого шага «Commit»: conventional commits, в конце сообщения `Co-Authored-By: Claude Code <noreply@anthropic.com>` (правило окружения).
- `.gitignore` с первого коммита: `node_modules/`, `dist/`, `.superpowers/`, `.env`.

## Review Focus

Пять классов входов, которые спека подразумевает, но явно не тестировала — каждый закреплён тестом в задаче-владельце:

1. **Не-GPX / битый файл при добавлении** (выбрали фото или обрезанный файл) → понятная русская ошибка, ничего не сохраняется. Тест в Task 2 (`parseGpxSegments` бросает `GpxParseError`) и Task 7 (форма показывает ошибку, кнопка сохранения заблокирована).
2. **GPX без точек трека** (только `wpt`, пустой `trk`) → ошибка «в файле нет точек», не молчание и не падение. Тест в Task 2.
3. **Гигантский GPX** (десятки тысяч точек, часовая запись) → карта не захлёбывается: для отрисовки сегменты прореживаются, `decimate` сохраняет концы. Тест в Task 5.
4. **Имя файла с кириллицей/пробелами/эмодзи** → в Storage путь только uuid, при скачивании возвращается `originalFilename`. Тесты в Task 3 (контракт) и Task 7 (download-атрибут).
5. **Инвариант основного района** — ровно один `isPrimary`; удаление непустого района невозможно. Тесты в Task 3 (репозиторий) и Task 8 (UI отключает/подсказывает).

- [ ] **Step 1: Тесты gpx (падают).** Фикстуры-строки прямо в тесте: (а) GPX с одним `trk/trkseg` из 3 `trkpt` → 1 сегмент; (б) два `trkseg` + один `rte` с `rtept` → 3 сегмента, порядок trk-сегменты затем rte; (в) `<html><body>x` → `GpxParseError`; (г) валидный XML без `trkpt/rtept` (только `wpt`) → `GpxParseError` с сообщением, содержащим «нет точек»; (д) пустая строка → `GpxParseError`.
- [ ] **Step 2: Реализация parseGpxSegments.** `new DOMParser().parseFromString(xml, 'application/xml')`; `doc.querySelector('parsererror')` → throw; собрать `trkseg → trkpt` как отдельные сегменты, затем все `rtept` одним сегментом; пусто → throw. `wpt` игнорируются.
- [ ] **Step 3: Тесты geo (падают).** `haversineKm({lat:0,lon:0},{lat:0,lon:1})` ≈ 111.19 ±0.1; `segmentsDistanceKm` двух сегментов = сумма; `segmentsBounds` по 3 точкам; `decimate([1..10], 5)` → длина 5, первый=1, последний=10; `decimate(arr, 1000)` при длине 10 → тот же массив.
- [ ] **Step 4: Реализация geo.** Haversine (радиус Земли 6371.0088 км), сумма по соседним точкам внутри сегментов (между сегментами не суммировать).

```ts
const R = 6371.0088, rad = (d: number) => d * Math.PI / 180;
const hav = (a: LatLng, b: LatLng) => {
  const dLat = rad(b.lat - a.lat), dLon = rad(b.lon - a.lon);
  const s = Math.sin(dLat/2)**2 + Math.cos(rad(a.lat)) * Math.cos(rad(b.lat)) * Math.sin(dLon/2)**2;
  return 2 * R * Math.asin(Math.sqrt(s));
};
```

- [ ] **Step 5: Тесты format (падают).** `formatKm(12.345) === '12,4 км'`; `formatKm(100) === '100 км'`; `formatKm(0.43) === '0,4 км'`. `validateTrackMeta`: пустое имя → сообщение про название; имя из 201 символа → ошибка; описание 1001 → ошибка; валидный ввод → `[]`.
- [ ] **Step 6: Реализация format.** `formatKm`: `Intl.NumberFormat('ru-RU', { maximumFractionDigits: 1 })` + `' км'`. `validateTrackMeta` — правила спеки: имя обязательное ≤200, описание ≤1000, категория из четырёх, район выбран.
- [ ] **Step 7: Прогнать все тесты — зелёные. `npx vitest run`.**

### Task 10: SQL-миграция Supabase

**Files:**
- Create: `supabase/migrations/0001_init.sql`, `docs/sql-review-checklist.md`

**Interfaces:**
- Produces: схема, на которую опирается Task 9 (имена выше) и инструкция Task 13. Локально не исполняется — применяется владелицей в Task 13; проверка — чеклистом ревью.

- [ ] **Step 1: Написать 0001_init.sql** (полный текст ниже — это единственное место плана, где код дан целиком, потому что ошибки в RLS/триггерах дорого находить при настройке):

```sql
create type category as enum ('hike','bike','run','ski');

create table districts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  name text not null check (length(trim(name)) between 1 and 100),
  is_primary boolean not null default false,
  created_at timestamptz not null default now()
);

create table tracks (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  district_id uuid not null references districts(id) on delete restrict,
  category category not null,
  name text not null check (length(trim(name)) between 1 and 200),
  description text check (description is null or length(description) <= 1000),
  distance_km numeric not null,
  original_filename text not null,
  storage_path text not null,
  min_lat double precision, min_lon double precision,
  max_lat double precision, max_lon double precision,
  preview text,
  gpx_parsed_at timestamptz not null default now(),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- ровно один основной район (проверка при записи)
create function assert_single_primary() returns trigger as $$
begin
  if new.is_primary and exists (
    select 1 from districts d
    where d.user_id = new.user_id and d.is_primary and d.id <> new.id
  ) then raise exception 'Основной район уже существует: снимите флаг перед сменой';
  end if;
  return new;
end $$ language plpgsql security definer;
create trigger trg_single_primary before insert or update on districts
  for each row execute function assert_single_primary();

-- регистрация закрыта: первый зарегистрировавшийся = владелец
create function reject_second_user() returns trigger as $$
begin
  if (select count(*) from auth.users) >= 1 then
    raise exception 'Регистрация закрыта: у приложения уже есть владелец';
  end if;
  return new;
end $$ language plpgsql security definer;
create trigger trg_one_owner before insert on auth.users
  for each row execute function reject_second_user();

alter table districts enable row level security;
alter table tracks enable row level security;
create policy owner_all_districts on districts for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy owner_all_tracks on tracks for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);

insert into storage.buckets (id, name, public) values ('gpx','gpx', false)
  on conflict (id) do nothing;
create policy owner_gpx_objects on storage.objects for all
  using (bucket_id = 'gpx' and owner = auth.uid())
  with check (bucket_id = 'gpx' and owner = auth.uid());
```

- [ ] **Step 2: Чеклист-ревью** (сохранить в `docs/sql-review-checklist.md`, пройтись по пунктам, галочки в PR-описании): RLS включён на обеих таблицах; политики только через `auth.uid() = user_id`; `on delete restrict` защищает удаление непустого района и на уровне БД; триггер регистрации не мешает первому входу; bucket приватный; анонимный (не залогиненный) доступ отсутствует.
